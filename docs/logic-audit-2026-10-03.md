# Аудит расчётов и сохранения данных приложения Мои деньги

Дата проверки: 3 октября 2026 года. Исходный коммит: `5e08c38`. Исправленная локальная сборка: `1.0.49`.

Баг свободного остатка исправлен. Редактор теперь изменяет ту же сумму, которую показывает карточка. Найдены и исправлены связанные ошибки отмены операций, валют, сохранения и сборки. Проверены исходники и собранное приложение; реальные данные с телефона пользователя в проверку не входили.

## Почему введённый остаток становился отрицательным

Главная карточка показывала **свободный остаток**, а её редактор устанавливал **баланс месяца до оставшихся планов**. После сохранения планы вычитались из введённой суммы.

Пример старого поведения: баланс 1 000 BYN, оставшиеся планы 700 BYN, свободно 300 BYN. При вводе 125,56 редактор устанавливал баланс 125,56, а карточка показывала −574,44 BYN.

Теперь создаётся корректировка `введённый свободный остаток − текущий свободный остаток`. В этом примере она равна −174,44 BYN: баланс становится 825,56, планы остаются 700, свободный остаток — ровно 125,56 BYN. При настоящем перерасходе отрицательные значения по-прежнему отображаются красным.

Проверка в браузере: ввод `125,56` при плане 700 BYN сохранил ровно `125,56 BYN`, класс карточки `status-good`; после перезагрузки число сохранилось, ошибок в журнале браузера не было.

## Действующие правила расчёта

Каждый расчётный месяц независим. Начало по умолчанию — 5-е число, конец — 4-е следующего месяца. Доходы и расходы будущего месяца не меняют текущий. Накопления, питомец, подарки и подушка — общие конверты с историей за все месяцы.

`Баланс месяца = доходы − расходы и переводы, уже учтённые в месячных итогах + отдельные корректировки и возвраты + сохранённая начальная корректировка этого месяца`.

`Свободный остаток = баланс месяца − оставшиеся планы`.

Расход внутри ещё не выполненного плана уменьшает баланс и остаток плана на одну сумму. Поэтому свободный остаток не списывается второй раз. Перерасход уменьшает свободный остаток. Для еды остатки закрытых недель больше не резервируются. Деньги округляются до копеек; ввод допускает точку и запятую.

Для накоплений и резерва месячный план означает сумму пополнений за месяц. Возврат из конверта увеличивает баланс месяца, но не стирает уже выполненное пополнение. Если нужен план по чистому приросту конверта, это отдельное изменение правила.

## Ограничения старых данных и дальнейшие решения

1. **У старых обменов нет `exchangeId`, у старых исправлений еды нет точного распределения изменений по неделям.** Новые записи исправлены. Автоматически угадывать связи старых записей по одинаковой сумме небезопасно. Решение: отдельная проверка резервной копии, связывание подтверждённых обменов и сверка недельных фактов по истории. Без исходных записей восстановить потерянное распределение нельзя.
2. **Старые пополнения подушки могли быть отдельно внесены в резерв.** Новые пополнения связываются автоматически. Решение для истории: сверить реальные переводы и `reserveAllocated`; объединять только подтверждённые дубли, иначе можно списать или вернуть деньги повторно.
3. **Наличные `cashNow` — справочная сумма; коммунальные из аванса — отдельная проходящая операция.** Они не прибавляются к свободному остатку и не вычитаются из основного дохода соответственно. Если наличные должны стать полноценным денежным счётом, решение — отдельный счёт наличных и переводы между источниками, вместо простого сложения поля с доходом.
4. **Сводка накоплений группируется по календарному месяцу даты, бюджет — по периоду зарплаты.** Это два разных среза, особенно с 1-го по 4-е число. Решение для единого среза — группировать сводку через `savingsTransactionPeriodKey`; сейчас её календарная группировка сохранена.
5. **Баланс питомца, подарков и накоплений допускает дефицит при расходах сверх конверта.** Это отдельный минус конверта, а не повторный расход общего бюджета. Если расход должен быть запрещён при нехватке денег, решение — единая проверка доступного остатка перед всеми внутренними списаниями.
6. **Одновременное редактирование в нескольких вкладках не объединяет изменения.** Очередь исправляет последовательные действия в одной вкладке. Для нескольких вкладок решение — блокировка записи через Web Locks и контроль ревизии с уведомлением о конфликте.
7. **Операции и месячные суммы всё ещё хранятся в двух представлениях.** Исправлены обнаруженные расхождения, добавлены проверки обратных операций. Чтобы новые функции реже ломали арифметику, следующий архитектурный шаг — единый журнал операций: месячные расходы и балансы конвертов вычислять из него, а отдельные суммы использовать только как пересчитываемый кэш. Миграцию проводить с сохранением снимка, сравнением итогов каждого месяца до/после и тестами восстановления.

Файл `docs/calculation-logic-ru.docx` остаётся архивным руководством старой модели общего счёта; актуальная инструкция — `docs/calculation-logic-ru.md`. Публикация обновления на GitHub Pages в рамках этой проверки не выполнялась.
